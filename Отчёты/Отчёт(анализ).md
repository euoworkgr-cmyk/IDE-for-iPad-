C#-патч не внедрён: обязательный архитектурный spike выявил существенные риски размера, PWA-кэширования и runtime-совместимости. В
  соответствии с требованиями патча я остановился до изменения production-кода Altitude.

  ## Результат spike

  Проверена связка:

  - .NET SDK 10.0.110
  - .NET WebAssembly
  - Roslyn Microsoft.CodeAnalysis.CSharp 5.0.0
  - локальная компиляция и запуск сборки через Assembly.Load
  - тестовый запуск в Chromium

  Официальный browser-WASM pipeline использует browser-wasm и генерируемый dotnet.js, но соответствующий workload/template всё ещё
  относится к experimental-инструментам. .NET WebAssembly Browser App
  (https://learn.microsoft.com/en-us/aspnet/core/client-side/dotnet-interop/wasm-browser-app?view=aspnetcore-10.0)

  Измерения:

  Roslyn-публикация содержит 855 файлов. Крупнейшие:

  - Microsoft.CodeAnalysis.CSharp.wasm — 6.83 MB

  В браузере spike завершился TypeLoadException при разрешении типов из System.Runtime, ещё до успешной компиляции первого Hello World.
  Следовательно, сейчас нет подтверждённой рабочей конфигурации даже для Chromium — тем более её нельзя безопасно выпускать на Safari/
  iPadOS.

  ## Почему внедрение остановлено

  - Добавление Roslyn увеличивает web assets примерно на 29 MB.
  - Runtime запрашивает сотни framework-файлов.
  - Текущий Workbox glob не включает ICU-файлы .dat.
  - Полный offline требует заранее кэшировать runtime. Это сделало бы загрузку runtime ленивой только по инициализации, но не по сетевому
    скачиванию.

  - Такой precache заметно утяжелит установку Service Worker и может быть нестабилен по памяти на реальном iPad.
  - Web Worker поддерживается официально начиная с .NET 10, но он решает отзывчивость UI, а не размер и runtime-ошибку. .NET on Web
    Workers (https://learn.microsoft.com/en-us/aspnet/core/client-side/dotnet-on-webworkers?view=aspnetcore-10.0)

  - JS/.NET interop технически доступен, но сам по себе не устраняет проблемы загрузки Roslyn. .NET JavaScript interop
    (https://learn.microsoft.com/en-us/aspnet/core/client-side/dotnet-interop/?view=aspnetcore-10.0)

  ## Что изменено

  Файлы Altitude не изменялись.

  Spike находился только во временном каталоге /tmp и не попал в проект. Поэтому:

  - PythonRuntime не изменён.
  - Pyodide assets не изменены.
  - импорт файлов, IndexedDB и SaveCoordinator не изменены.
  - Service Worker и Workbox-конфигурация не изменены.
  - C# Run, diagnostics, stdin и runtime cache не добавлялись.
  - Новые unit-тесты C# не добавлялись, поскольку production-функция не реализована.

  ## Контрольная проверка Altitude

  - npm run check — успешно.
  - npm test — успешно, 29/29 тестов.
  - npm run build — успешно.
  - Production precache — 20 файлов, 13,966.43 KiB.
  - dist — 17 MB.
  - Локальные Pyodide assets присутствуют, включая WASM и Python stdlib.

  Существующее поведение сохраняется: .cs можно импортировать, открывать и сохранять, но Run остаётся недоступной, поскольку
  подтверждённого C# runtime пока нет.

  ## Рекомендация

  Перед production-патчем нужен отдельный экспериментальный этап:

  1. Получить успешно работающий минимальный Roslyn compile/run в Chromium.
  2. Уменьшить reference assemblies, satellite resources и количество framework assets.
  3. Перенести runtime в Web Worker.
  4. Проверить cold start, повторный запуск и расход памяти на реальном iPad.
  5. Отдельно согласовать компромисс: большой обязательный precache либо опциональная предварительная offline-установка C# runtime.

  На iPad сейчас достаточно повторно проверить регрессию существующих Import File, Python Run и offline-запуска. Проверять C# execution
  пока нечего — рискованный runtime в Altitude намеренно не добавлен.
