Hotfix реализован точечно.

  1. Точная причина

  Проблему создавал параметр:

  autoEOF: false

  В Pyodide 314.0.3 line-based stdin callback возвращает целую строку, а Pyodide самостоятельно добавляет \n.

  При autoEOF: false внутренний LegacyReader после этой строки продолжал заполнять текущий большой read-buffer и немедленно снова вызывал
  callback. Поэтому один Python input() мог открывать множество browser prompt. Cancel возвращал пустую строку, превращался в строку с
  newline, после чего чтение также продолжалось.

  2. Как было

  pyodide.setStdin({
    stdin: hooks.readInput,
    autoEOF: false
  });

  stdout/stderr использовали byte writers с TextDecoder.

  3. Как стало

  Добавлена тестируемая configureLineStdin():

  pyodide.setStdin({
    stdin: () => readInput() ?? "",
    isatty: false
  });

  autoEOF не переопределяется — используется штатное поведение Pyodide autoEOF: true.

  stdout/stderr остались byte-based и не изменялись.

  4. Почему теперь один prompt на один input()

  Callback возвращает одну полную строку. Pyodide:

  - добавляет newline;
  - передаёт строку Python;
  - завершает текущую операцию чтения;
  - повторно вызывает callback только при следующем явном input().

  В production browser smoke калькулятор вызвал callback ровно три раза.

  5. Cancel

  window.prompt() возвращает null, который stdin-обёртка преобразует в пустую строку "".

  Python получает пустую строку один раз. Повторной попытки и бесконечного prompt нет. UI продолжает выводить уведомление:

  [Input cancelled; using an empty string.]

  Для int(input()) пустая строка ожидаемо приведёт к ValueError, который появится в traceback.

  7. Regression tests

  На настоящем локальном Pyodide/WASM проверены:

  - один input() → один callback, результат Alice;
  - три input() → ровно три callback;
  - два int(input()) с 10 и 20 → 30;
  - Cancel → одна пустая строка без retry;
  - Unicode Привет без повреждения;
  - полный калькулятор с 10, 20, + → 30 и ровно три callback;
  - конфигурация stdin не содержит autoEOF: false.

  9. Что проверить на iPad

  Запустить:

  print("Калькулятор")

  a = int(input("Введите первое число: "))
  b = int(input("Введите второе число: "))
  choice = input("Введите операцию (+, -, *, /): ")

  if choice == "+":
      print(a + b)
  elif choice == "-":
      print(a - b)
  elif choice == "*":
      print(a * b)
  elif choice == "/":
      print(a / b)

  Ввести последовательно:

  10
  20
  +

  Ожидается ровно три системных окна и результат:

  30

  Также проверить:

  - один input() — одно окно;
  - Cancel на строковом input() — выполнение продолжается с пустой строкой;
  - Привет возвращается без искажения;
  - повторить тест в авиарежиме с Wi‑Fi OFF.
